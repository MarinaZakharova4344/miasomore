# Онлайн-бронирование по схеме зала

```
Сайт (GitHub Pages) ──► Cloudflare Worker ──► база D1 (SQLite)
   схема зала,              проверка правил,     брони и занятые места,
   выбор мест                транзакция           триггер против двойной брони
                                 │
                                 └──► Telegram: бронь администратору,
                                      кнопка «Отменить», команды /today и /tomorrow
```

## Правила

| | |
|---|---|
| Часы работы | 10:00–22:00, время выбирается с шагом 30 минут |
| Длительность брони | 3 часа (бронь с 20:00 и позже заканчивается в 22:00) |
| Последнее время начала | 21:00 |
| Опоздание | места держим 15 минут — об этом сказано на сайте, в подтверждении и в Telegram |
| Столы 1–3 | бронируются только целиком, до 4 гостей |
| Стойки А1–А3, О1–О4 | по одному месту |
| На сколько вперёд | 30 дней |
| Ограничение | не больше 2 броней на один телефон в день |
| Подтверждение | автоматическое, если места свободны |

Правила и схема мест заданы в начале `booking-worker.js` (`RESOURCES`, `OPEN`, `DURATION`…), а координаты мест на схеме — в `js/booking.js`. Если меняете столы, меняйте оба файла.

## Как устроена защита от двойной брони

1. Бронь записывается **одной транзакцией** (`DB.batch`): строка в `bookings` и по строке в `booking_items` на каждый стол или место.
2. Триггер `no_double_booking` в базе перед вставкой места проверяет, нет ли активной брони того же места, пересекающейся по времени (`start < другой_end И другой_start < end`). Если есть, он прерывает вставку, и откатывается вся бронь целиком.
3. D1 выполняет записи строго по очереди, поэтому из двух одновременных запросов на одно место проходит ровно один. Второй гость получает ответ 409, и сайт показывает ему «Пока вы выбирали, эти места заняли…».

Это аналог exclusion constraint из PostgreSQL. Проверка «свободно ли» живёт в самой базе, а не в коде, который можно обойти.

## Тесты

```
cd worker
npm test
```

12 тестов на настоящем SQLite (встроен в Node 22+), с тем же SQL и триггером, что в D1. Среди них:
- 20 одновременных запросов на одно место — проходит ровно один;
- бронь двух мест, одно из которых занято, — не сохраняется ни одно;
- брони встык (16:00–19:00 и 19:00–22:00) разрешены, пересекающиеся — нет;
- отмена через Telegram освобождает место.

Если убрать триггер, тесты на двойную бронь падают.

## Настройка в Cloudflare (один раз)

### 1. Создать базу
1. В Cloudflare откройте **Storage & Databases → D1 SQL Database → Create**.
2. Имя: `miasomore-booking`. Нажмите **Create**.

Таблицы создавать не нужно: Worker сам создаёт их при первом запросе.

### 2. Подключить базу к Worker'у
1. **Workers & Pages → miasomore-booking → Settings → Bindings → Add → D1 database**.
2. **Variable name:** `DB` (ровно так, большими буквами), **D1 database:** `miasomore-booking`.
3. Нажмите **Deploy** (или **Save**).

### 3. Обновить код
1. **Edit code**, удалите всё и вставьте содержимое `worker/booking-worker.js`.
2. Нажмите **Deploy**.

Переменные `BOT_TOKEN`, `CHAT_ID`, `ALLOWED_ORIGINS` остаются прежними.

### 4. Проверить
Откройте в браузере (подставьте завтрашнюю дату):
```
https://miasomore-booking.mooorrriinaa.workers.dev/availability?date=2026-10-19
```
Должно появиться `{"ok":true, … "busy":[]}`. Если видите `"error":"no_db"`, значит не сделан шаг 2.

### 5. Кнопка «Отменить» и команды в Telegram (необязательно, но удобно)
Без этого шага брони приходят в Telegram, но отменить их можно только в базе.

1. В **Settings → Variables and Secrets** добавьте `TG_SECRET` с типом **Secret**: любая длинная строка из латинских букв и цифр, например `mm2026bookingKey81`. Нажмите **Deploy**.
2. Откройте в браузере ссылку, подставив свой токен бота и тот же секрет:
   ```
   https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://miasomore-booking.mooorrriinaa.workers.dev/tg&secret_token=<TG_SECRET>
   ```
   Должно появиться `"ok":true, "description":"Webhook was set"`.

После этого:
- под каждой бронью в Telegram есть кнопка **❌ Отменить бронь** — места сразу освобождаются на сайте;
- команда `/today` в чате с ботом присылает список броней на сегодня, `/tomorrow` — на завтра.
